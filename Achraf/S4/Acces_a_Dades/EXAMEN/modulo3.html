M3: JPA y Bases de Datos de Objetos

Persistencia mediante ORM (JPA) y gestión del ciclo de vida de las entidades

Progreso Global:

1 El concepto de ORM y JPA

El mapeo objeto-relacional (**ORM**) es una técnica que permite guardar y recuperar objetos de una base de datos sin tener que escribir SQL nativo.
**JPA (Jakarta Persistence API)** es la especificación estándar de Java que define cómo se debe comportar un ORM, mientras que **EclipseLink** o **Hibernate** son implementaciones de esta API. También se utiliza en bases de datos de objetos nativas como **ObjectDB**.

Anotaciones de definición básicas:

  • @Entity: Especifica que la clase representa una entidad de base de datos.
  • @Table(name = "nombre"): Permite cambiar el nombre físico de la tabla asociada.
  • @Id: Define el atributo que actúa como clave primaria.
  • @Column(length = X, unique = true): Configura propiedades físicas del campo (longitud, restricciones).

2 Requisitos de Entidad y Relaciones

Para que una clase actúe como una entidad JPA persistente, debe cumplir con especificaciones estrictas:

  • Constructor vacío: Es obligatorio incluir un constructor público o protegido sin parámetros (sin argumentos). Si usas Lombok, se logra con la anotación @NoArgsConstructor.
  • Interfaz Serializable: La clase debe implementar la interfaz java.io.Serializable para permitir su transmisión o persistencia binaria.
  • Relaciones Bidireccionales (1 a N):
    En el lado 1 (padre, ej: Estacio), se declara @OneToMany(mappedBy = "estacio", cascade = CascadeType.ALL, orphanRemoval = true).
    En el lado N (hijo, ej: Pista), se declara el campo de referencia con @ManyToOne.
  • Relación Uno a Uno (1 a 1 Bidireccional):
    En el lado dominante de la relación (el que almacena físicamente la clave ajena en base de datos), se coloca la anotación @OneToOne acompañada de @JoinColumn(name = "id_del_otro").
    En el lado inverso (el no dominante), se coloca la anotación @OneToOne(mappedBy = "campo_en_la_otra_clase"). Fíjate en que el valor de mappedBy debe coincidir con el nombre de la propiedad en la clase dominante, no con el nombre de la columna física de la base de datos.

3 Ciclo de vida, EntityManager y ObjectDB

El EntityManager (gestor de persistencia) controla el estado de las entidades en memoria intermedia y gestiona las operaciones con la BD.

🌐

Configuración y Modos en ObjectDB

ObjectDB es una base de datos orientada a objetos que implementa JPA. Se configura en el archivo persistence.xml con el proveedor objectdb.jpa.Provider y soporta dos modos de funcionamiento mediante el formato de la URL de conexión:
• Modo Embebido (local): Se especifica una ruta de archivo local (ej: db/persistencia.odb o simplemente persistencia.odb). Los objetos se guardan directamente en este archivo.
• Modo Servidor: Se especifica una dirección IP y puerto (ej: objectdb://localhost:6136/persistencia.odb). Requiere que el servidor ObjectDB esté ejecutándose por separado.

⚠️

Gestión de Transacciones

Todos los cambios que modifiquen la base de datos (persist, remove, merge) requieren ejecutarse dentro de una transacción. El patrón consiste en iniciar la transacción con em.getTransaction().begin(), aplicar los métodos de persistencia y finalizar con em.getTransaction().commit(). En caso de error, debe ejecutarse em.getTransaction().rollback() para restaurar el estado previo.

  • find(Class, ID): Busca y devuelve un registro de la BD por su ID. **No requiere transacción**.
  • persist(objeto): Guarda un objeto nuevo en la base de datos.
  • remove(objeto): Elimina un registro de la base de datos. **Muy importante:** Primero debe buscarse con find (para que esté vinculado al EntityManager) y luego pasarse al remove.
  • merge(objeto): Sincroniza un objeto modificado en memoria que se encuentra desvinculado (detached) del EntityManager actual. Si el objeto no existe todavía en la base de datos, el método merge lo dará de alta automáticamente (actúa como "upsert").

4 JPQL (Java Persistence Query Language)

JPQL es un lenguaje de consultas orientado a objetos. En lugar de realizar consultas SQL contra tablas físicas de la base de datos, se escriben consultas dirigidas a las **clases de Java** (entidades) y sus atributos.

Ejemplo de JPQL: SELECT e FROM Estacio e WHERE e.altitudMaxima > :altitud (referencia directa a la clase Estacio y variable altitudMaxima).

Definición de Entidades y Relaciones

Java 
@Entity
public class Estacio {
    @Id
    @Column(length = 14)
    private String id;
    
    @OneToMany(mappedBy = "estacio", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Pista> pistes = new ArrayList<>();
}

@Entity
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)
public abstract class Pista {
    @Id
    private String id;
    
    @ManyToOne
    private Estacio estacio;
}

Operaciones de l'EntityManager (Transacciones)

Java 
// Método para borrar una estación con su EntityManager
public void esborraEstacio(String id) {
    // 1. Primero es necesario buscar el registro
    Estacio estacio = em.find(Estacio.class, id);
    if (estacio == null) return;
    
    // 2. Abrir transacción para realizar el borrado físico
    try {
        em.getTransaction().begin();
        em.remove(estacio); // Borrado físico (y por cascada, sus pistas hijas)
        em.getTransaction().commit();
    } catch (Exception e) {
        em.getTransaction().rollback(); // Deshacer cambios en caso de fallo
        throw e;
    }
}

Consultas JPQL con parámetros

Java 
// Obtener pistas rojas de una estación concreta
String query = "SELECT p FROM Pista p WHERE p.estacio.id = :idEstacio AND p.color = :color";
List<Pista> pistas = em.createQuery(query, Pista.class)
    .setParameter("idEstacio", "ST-A1")
    .setParameter("color", "roja")
    .getResultList();

¿Qué diferencia persist() de merge()?
Haz clic para girar

persist() sirve para guardar objetos nuevos en la base de datos (estados transitorios sin representación previa).

merge() actualiza un objeto que se encuentra desvinculado (detached) del contexto persistente actual de JPA.

¿Qué hace la propiedad orphanRemoval = true?
Haz clic para girar

Si se elimina una entidad hija de la lista de colección del padre (ej: borrar una pista de la lista pistes de Estacio), esta se borrará físicamente del disco duro.

¿Se puede borrar directamente un objeto nuevo instanciado?
Haz clic para girar

No. Para eliminar un registro con remove(), primero debe recuperarse mediante find().

Si se crea un objeto en memoria únicamente con el ID y se pasa a remove, JPA lanzará un error.

¿Cuál es la diferencia entre JPQL y SQL?
Haz clic para girar

SQL realiza las consultas directamente sobre nombres de columnas y tablas físicas relacionales.

JPQL trabaja con los nombres de las **clases de entidad Java** y sus **atributos miembro** definidos.

Requisitos obligatorios de una entidad JPA
Haz clic para girar

1. Estar anotada con @Entity.

2. Tener constructor público/protegido sin argumentos.

3. Implementar la interfaz java.io.Serializable.

4. Definir una propiedad identificadora con @Id.

¿Qué implica SINGLE_TABLE en JPA?
Haz clic para girar

Mapea una jerarquía completa de herencia Java a una única tabla física, usando una columna de discriminación para distinguir las clases.

¿find() vs getReference()?
Haz clic para girar

find() realiza la consulta de inmediato (Eager). getReference() devuelve un proxy perezoso (Lazy) que solo consultará la base de datos cuando se acceda a sus atributos.

¿Qué es la caché de primer nivel (L1)?
Haz clic para girar

Es el contexto de persistencia asociado al EntityManager. Si solicitas el mismo registro por ID dos veces en la misma transacción, no se repite la consulta SQL.

1. ¿Qué métodos de EntityManager requieren obligatoriamente la ejecución de una transacción?
  • Únicamente el método find().
  • Los métodos de escritura/modificación: persist(), remove() y merge().
  • Cualquier tipo de consulta ejecutada mediante JPQL.
2. En una relación bidireccional 1 a N, ¿dónde debe colocarse la propiedad 'mappedBy'?
  • En el lado 1 (clase padre) de la relación con la anotación @OneToMany.
  • En el lado N (clase hija) de la relación con la anotación @ManyToOne.
  • Debe definirse obligatoriamente en ambos extremos de la relación.
3. ¿Qué consulta JPQL es correcta para recuperar todas las pistas con espesor de nieve (gruixNeu) mayor a 20?
  • SELECT p FROM pistes p WHERE p.gruix_neu > 20
  • SELECT * FROM Pista p WHERE p.gruixNeu > 20
  • SELECT p FROM Pista p WHERE p.gruixNeu > 20
4. Si borramos una entidad padre con CascadeType.REMOVE o CascadeType.ALL, ¿qué sucede con sus entidades hijas asociadas?
  • Permanecen huérfanas en la base de datos sin clave foránea.
  • Se eliminan automáticamente de la base de datos en cascada.
  • Lanza una excepción de integridad referencial SQL y falla.
5. ¿Cuál es el comportamiento de em.find(Clase.class, pk) si el registro no existe en la base de datos?
  • Devuelve null.
  • Lanza una excepción NoResultException.
  • Lanza una excepción EntityNotFoundException.
6. ¿Qué método de Query o TypedQuery se utiliza para inyectar valores en los parámetros con nombre (:nombreParametro) definidos en JPQL?
  • setVariable("nombre", valor)

7. ¿Qué anotación de JPA se utiliza para indicar que un atributo de una clase entidad Java NO debe ser mapeado en ninguna columna de la base de datos?
  • @Transient

8. ¿Cuál es la estrategia de carga (FetchType) predeterminada por JPA para las relaciones de tipo @ManyToOne?
  • FetchType.LAZY (carga perezosa).

  • FetchType.EAGER (carga inmediata).
9. ¿Qué método de EntityManager debemos invocar para volcar o sincronizar de forma inmediata todos los cambios pendientes en memoria con la base de datos antes de hacer commit?
