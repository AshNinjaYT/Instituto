M2: JDBC y PostgreSQL Objeto-Relacional

Conexión nativa en Java y manipulación de arrays SQL y tipos estructurados

Progreso Global:

1 Funcionamiento de la API JDBC

JDBC (Java Database Connectivity) es la especificación estándar de Java para conectar con bases de datos relacionales. Emplea controladores (drivers) específicos para cada base de datos (como org.postgresql.Driver).

Ciclo de vida de la conexión:

  • Conexión: Se obtiene mediante DriverManager.getConnection(url, usuario, contraseña).
  • Ejecución: Se preparan y ejecutan sentencias SQL.
  • Liberación: Siempre hay que cerrar los recursos (Connection, Statement, ResultSet) con close() o utilizando una estructura try-with-resources.
💥

PostgreSQL y la Sensibilidad a Mayúsculas

A PostgreSQL no le gustan las mayúsculas en los nombres de tablas o columnas. Por defecto, Postgres convierte cualquier identificador sin comillas a minúsculas (ej: MiTabla se convierte en mitabla).
Peligro: Si en Java utilizas anotaciones JPA como @Table(name="\"Persona\"") (con comillas dobles explícitas), obligas a Postgres a buscar la tabla respetando estrictamente las mayúsculas. Si la tabla se creó sin comillas, se guardará como persona (minúscula) y tu aplicación lanzará un error de "tabla no encontrada".
Regla de oro: Define siempre todas tus tablas, columnas e identificadores SQL en minúsculas.

2 Sentencias preparadas: PreparedStatement

A diferencia del Statement básico, un PreparedStatement precompila la sentencia SQL. Esto mejora el rendimiento de ejecuciones repetidas y, lo más importante, previene ataques de inyección SQL al escapar automáticamente los parámetros representados por el carácter ?.

Métodos de ejecución clave (incluidos a examen):

  • executeQuery(): Se utiliza para operaciones de lectura (SELECT). Devuelve un objeto ResultSet.
  • executeUpdate(): Se utiliza para operaciones de escritura (INSERT, UPDATE, DELETE). Devuelve un entero (int) que indica el número de filas afectadas.

3 Extensiones OR de PostgreSQL: ROW y Arrays

PostgreSQL es un motor Objeto-Relacional. Permite definir tipos de datos estructurados propios y guardar arrays de datos en una sola columna.

  • Tipos compuestos (Composite Types): Se definen en la base de datos con CREATE TYPE dades_tecniques AS (longitud_m INTEGER, pendent_max INTEGER);. En Java, para insertarlos, se utiliza la función ROW(?, ?)::nombre_tipo en la sentencia insert.
  • Arrays SQL: Para guardar arrays en la base de datos, utilizamos métodos nativos de JDBC.
    En la escritura, se convierte una lista de Java usando conn.createArrayOf("tipo", array).
    En la lectura, se obtiene el objeto nativo de la base de datos utilizando (String[]) resultSet.getArray("columna").getArray().
  • Operador ANY: Para buscar elementos dentro de listas en consultas SQL, utilizamos el operador ANY en la cláusula WHERE, el cual comprueba si un valor individual coincide con cualquiera de los elementos del array SQL.

CRUD básico con PreparedStatement

Java 
// Borrar pistas no operativas
String sql = "DELETE FROM pista WHERE oberta = ? AND color = ?";
try (PreparedStatement ps = con.prepareStatement(sql)) {
    ps.setBoolean(1, false);
    ps.setString(2, "negra");
    
    int filasAfectadas = ps.executeUpdate();
    System.out.println("Filas borradas: " + filasAfectadas);
}

Insertar Composite Type (ROW) en PostgreSQL

Java 
// Insertar datos combinando ROW y casting al tipo complejo dades_tecniques
String sql = "INSERT INTO pista (id, nom, especificacions) VALUES (?, ?, ROW(?, ?, ?)::dades_tecniques)";
try (PreparedStatement ps = con.prepareStatement(sql)) {
    ps.setString(1, pista.getId());
    ps.setString(2, pista.getNom());
    ps.setInt(3, pista.getLongitud());    // ROW elemento 1
    ps.setInt(4, pista.getDesnivell());    // ROW elemento 2
    ps.setInt(5, pista.getPendentMax());    // ROW elemento 3
    
    ps.executeUpdate();
}

Insertar, leer y buscar en Arrays SQL

Java 
// 1. Escribir un Array de Java a Postgres
List<String> remontes = Arrays.asList("Telesilla Norte", "Teleesquí Sur");
java.sql.Array sqlArray = con.createArrayOf("varchar", remontes.toArray());
ps.setArray(6, sqlArray);

// 2. Leer un Array de Postgres a Java
java.sql.Array resultSqlArray = rs.getArray("remuntadors_acces");
String[] arrayElementos = (String[]) resultSqlArray.getArray();
List<String> listaJava = Arrays.asList(arrayElementos);

// 3. Buscar en consultas utilizando el operador ANY
String sqlBusqueda = "SELECT * FROM pista WHERE ? = ANY(remuntadors_acces)";
// Filtra las pistas que tienen el remonte especificado

¿Por qué executeUpdate() devuelve un entero (int)?
Haz clic para girar

Devuelve la cantidad de filas de la base de datos que se han visto afectadas por el cambio (modificadas, insertadas o borradas).

Permite verificar si la operación se completó con éxito (ej: si devuelve 0 filas, no se ha eliminado nada).

¿Cómo se evita la inyección SQL en JDBC?
Haz clic para girar

Utilizando siempre PreparedStatement con parámetros posicionales (?) en lugar de concatenar directamente las variables en el texto.

El driver escapa automáticamente cualquier carácter especial de las variables introducidas.

¿Cómo se representa un tipo estructurado ROW en la sentencia INSERT de JDBC?
Haz clic para girar

Se define utilizando la sintaxis SQL nativa: ROW(?, ?, ?)::nombre_tipo.

Desde Java se asignan como parámetros individuales ordenados en el PreparedStatement.

¿Para qué sirve try-with-resources en JDBC?
Haz clic para girar

Cierra automáticamente cualquier recurso o conexión declarada en el bloque try una vez terminado (incluso si ocurren excepciones).

Evita fugas de memoria o bloqueos de conexiones en el servidor de BD.

¿Cómo creamos un Array SQL en JDBC?
Haz clic para girar

Invocando al método connection.createArrayOf("tipo", arrayJava.toArray()).

Luego se asigna al PreparedStatement llamando a setArray(index, sqlArray).

¿Qué excepción es lanzada por JDBC ante cualquier fallo?
Haz clic para girar

La excepción comprobada (checked exception) java.sql.SQLException. Obliga a capturarse o declararse en la firma del método.

¿Diferencia entre Statement y PreparedStatement?
Haz clic para girar

Statement compila el SQL en cada ejecución (más lento e inseguro). PreparedStatement precompila la estructura, ofreciendo seguridad contra inyecciones SQL.

¿Qué es un Pool de Conexiones?
Haz clic para girar

Un conjunto de conexiones ya abiertas y preparadas en memoria que se reutilizan para no pagar el coste de abrir una nueva sesión física en cada consulta.
