M1: Ficheros y Serialización

Persistencia física mediante estructuras de ficheros de texto, XML y JSON

Progreso Global:

1 La clase File y Argumentos de Línea de Comandos

La clase java.io.File se utiliza como enlace físico a un recurso del sistema de archivos (archivo o directorio). No permite leer o escribir el contenido en sí, sino verificar y modificar sus descriptores o atributos externos.

Métodos de metadatos evaluados en el examen:

  • exists(): Comprueba si la ruta existe realmente.
  • isFile(): Verifica si la ruta apunta a un archivo ordinario de datos.
  • isDirectory(): Verifica si la ruta corresponde a una carpeta.
  • length(): Devuelve el tamaño en Bytes del archivo (tipo long).
  • isHidden(): Indica si el archivo está oculto según los atributos del S.O.
  • canRead(), canWrite(), canExecute(): Comprueban los permisos activos.
⚠️

Peligro: ArrayIndexOutOfBoundsException con Argumentos

El método main(String[] args) recoge los parámetros pasados desde la línea de comandos en el vector args.
Error típico de examen: Si intentas acceder a args[0] o args[1] sin verificar antes su longitud (args.length), el programa lanzará una excepción ArrayIndexOutOfBoundsException si el usuario olvida pasar dichos parámetros. Siempre debes validar la longitud del array antes de acceder a sus índices.

2 Flujos de datos (Streams y Buffers)

Para acceder al contenido interno de los ficheros utilizamos Streams. Un stream es una secuencia ordenada de bytes que conecta la aplicación con el medio físico.

A. Flujos de Bytes (Binario)

Tratan las dades bit a bit. Ideales para imágenes, archivos ejecutables o flujos binarios directos.
Clases abstractas: InputStream e OutputStream.
Implementación típica: FileInputStream / FileOutputStream.

B. Flujos de Caracteres (Texto)

Adecuados para texto plano, decodificando los bytes a caracteres mediante codificaciones (ej. UTF-8).
Clases abstractas: Reader y Writer.
Implementación típica: FileReader / FileWriter.

⚡

Manejo de Buffers

El acceso directo a disco es lento. Envolver los streams con un buffer (ej. BufferedReader) permite almacenar bloques grandes de datos en la memoria RAM para procesarlos. Con BufferedReader podemos usar readLine() para leer línea a línea cómodamente. Recuerda llamar a flush() para "empujar" las dades de los buffers de escritura hacia el disco antes de cerrar con close().

3 Filtrado: FileFilter

El método listFiles() acepta una instancia de la interfaz funcional FileFilter. Esta tiene un único método accept(File pathname) que decide si incluir o excluir el archivo analizado del listado.

En Java moderno, se escribe directamente en formato de expresión lambda para mantener el código limpio y legible.

4 Serialización XML (JAXB) y JSON (Gson)

La serialización transforma el estado de un objeto Java en memoria a un formato de texto persistible (XML o JSON). La deserialización recupera el objeto original desde ese texto.

Anotaciones JAXB principales:

  • @XmlRootElement(name = "root"): En la clase raíz del XML.
  • @XmlType(propOrder = {...}): Define el orden estricto de renderizado de los campos hijos.
  • @XmlAttribute: Guarda el atributo en la cabecera de la etiqueta (ej. <estacio id="1">).
  • @XmlElementWrapper(name = "contenedor"): Genera un tag envolvente para una lista de subnodos.

Gson:

  • @SerializedName("nombre_json"): Mapea propiedades cuando el nombre del campo en Java no coincide con la clave JSON.
  • Métodos principales: toJson() y fromJson().

FileFilter con Lambdas

Java 
// Crear un filtro que busque archivos .json de tamaño superior a 10KB
FileFilter filtro = archivo -> {
    if (archivo.isDirectory()) return false;
    boolean correctoExt = archivo.getName().endsWith(".json");
    boolean correctoTam = archivo.length() > 10240; // 10KB
    return correctoExt && correctoTam;
};

File directorio = new File("D:/datos");
File[] archivosFiltrados = directorio.listFiles(filtre);

JAXB Marshaller & Unmarshaller

Java 
// 1. Marshalling (Java a XML)
JAXBContext context = JAXBContext.newInstance(Estacio.class);
Marshaller marshaller = context.createMarshaller();
marshaller.setProperty(Marshaller.JAXB_FORMATTED_OUTPUT, true);
marshaller.marshal(objetoEstacion, new File("estacion.xml"));

// 2. Unmarshalling (XML a Java)
Unmarshaller unmarshaller = context.createUnmarshaller();
Estacio estacionRecuperada = (Estacio) unmarshaller.unmarshal(new File("estacion.xml"));

Gson Serialización JSON

Java 
// 1. Serialización (Java a JSON String y escritura en fichero)
Gson gson = new GsonBuilder().setPrettyPrinting().create();
String jsonString = gson.toJson(objetoEstacion);

try (FileWriter writer = new FileWriter("estacion.json")) {
    writer.write(jsonString);
}

// 2. Deserialización (Fichero JSON a Java)
try (FileReader reader = new FileReader("estacion.json")) {
    Estacio estacion = gson.fromJson(reader, Estacio.class);
}

¿Qué diferencia hay entre InputStream y Reader?
Haz clic para girar

InputStream lee los datos byte a byte (ideal para dades binarias como imágenes o archivos serializados de Java).

Reader está diseñado para flujos de caracteres (texto plano, decodificando el texto en UTF-8 o similar).

¿Qué utilidad tiene @XmlElementWrapper en JAXB?
Haz clic para girar

Sirve para agrupar listas de objetos bajo un tag XML contenedor.

Por ejemplo, envuelve varios subnodos <pista> dentro de una etiqueta externa <pistes>.

¿Para qué sirve la anotación @SerializedName de Gson?
Haz clic para girar

Vincula el nombre de un atributo de la clase Java con una clave JSON con nombre diferente.

Ejemplo: @SerializedName("fecha_alta") String fecha; genera la clave "fecha_alta": "valor" en el JSON.

¿Qué función tiene el método flush()?
Haz clic para girar

Vacía el buffer de escritura enviando cualquier dato pendiente directamente al almacenamiento físico en el disco duro.

Evita pérdidas de datos que se queden pendientes en la RAM.

¿Por qué es crítico validar args.length en main?
Haz clic para girar

Para evitar un error en tiempo de ejecución del tipo ArrayIndexOutOfBoundsException si el usuario olvida pasar los parámetros por línea de comandos.

¿Diferencia entre FileInputStream y FileReader?
Haz clic para girar

FileInputStream lee bytes puros (8 bits, datos binarios/imágenes).

FileReader lee caracteres (16 bits, texto plano decodificado mediante codificación de caracteres).

¿Cómo evitamos que JAXB serialice un campo a XML?
Haz clic para girar

Anotando el atributo o su método getter correspondiente con la anotación @XmlTransient.

¿Cómo lee BufferedReader una línea de texto?
Haz clic para girar

Llamando al método readLine(), que lee hasta encontrar un salto de línea y devuelve el String correspondiente (o null si alcanza el fin de fichero).

¿Qué es @XmlAccessorType en JAXB?
Haz clic para girar

Configura si JAXB debe buscar las propiedades leyendo las variables privadas (XmlAccessType.FIELD) o los métodos getter/setter (XmlAccessType.PROPERTY).

  • Serializar un objeto Java a un archivo XML físico en el disco.
  • Deserializar o transformar un documento XML en una instancia de objeto Java en memoria.
  • Configurar la jerarquía de tags ordenados para la escritura.
3. Si queremos un diseño eficiente en la lectura de archivos de texto grande, ¿cuál es la estructura correcta?
  • Envolver un FileOutputStream con un BufferedWriter.
  • Hacer uso de un FileInputStream sin buffers de memoria intermedia.
  • Envolver un FileReader dentro de un BufferedReader.

  • ArrayIndexOutOfBoundsException
